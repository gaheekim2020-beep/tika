# Feature Specification: 티켓 생성 API

**Feature Branch**: `[001-create-ticket-api]`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "API_SPEC.md의 POST /api/tickets 명세를 확인하고 구현에 필요한 요구사항을 정리해줘."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 제목만으로 빠르게 할 일 등록 (Priority: P1)

사용자는 떠오른 할 일을 다른 정보 없이 제목만 입력해 즉시 등록하고 싶어한다. 등록된 할 일은 Backlog 칼럼의 맨 위에 나타나야, 방금 추가한 항목을 바로 확인할 수 있다.

**Why this priority**: 제목만으로 생성하는 것이 가장 빈번하고 핵심적인 흐름이다. 이 흐름 없이는 앱의 기본 가치(빠른 할 일 등록)가 성립하지 않는다.

**Independent Test**: 제목 문자열 하나만 제출해서 새 항목이 Backlog 칼럼 최상단에 나타나는지, 그리고 우선순위/설명 등 나머지 값이 합리적인 기본값으로 채워지는지 확인하는 것만으로 완전히 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** Backlog 칼럼에 기존 항목이 있는 상태에서, **When** 사용자가 제목만 입력해 등록하면, **Then** 새 항목이 Backlog 칼럼의 가장 위에 나타나고, 설명은 비어 있으며 우선순위는 "보통"으로 표시된다.
2. **Given** Backlog 칼럼이 비어 있는 상태에서, **When** 사용자가 제목만 입력해 등록하면, **Then** 새 항목이 Backlog 칼럼에 등록된다.
3. **Given** 아무 항목도 입력하지 않은 상태에서, **When** 사용자가 제목 없이(또는 공백만 입력해) 등록을 시도하면, **Then** 등록이 거부되고 "제목을 입력해주세요"라는 안내가 표시된다.
4. **Given** 200자를 초과하는 제목을 입력한 상태에서, **When** 사용자가 등록을 시도하면, **Then** 등록이 거부되고 제목 길이 제한을 안내하는 메시지가 표시된다.

---

### User Story 2 - 상세 정보를 포함해 할 일 등록 (Priority: P2)

사용자는 할 일을 등록하면서 설명, 우선순위, 시작예정일, 종료예정일까지 함께 입력해 더 구체적인 계획을 세우고 싶어한다.

**Why this priority**: User Story 1(제목만 등록)이 동작한 뒤에 추가로 필요한 확장 시나리오다. 제목만으로도 앱은 동작하지만, 상세 정보 입력은 실제 업무 관리에 필요한 부가 가치를 제공한다.

**Independent Test**: 제목과 함께 설명, 우선순위, 날짜를 모두 채워 제출했을 때 입력한 값이 그대로 저장되어 응답에 반영되는지 확인하는 것으로 독립적으로 테스트 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 등록 화면에 있을 때, **When** 제목, 설명, 우선순위(낮음/보통/높음 중 선택), 시작예정일, 종료예정일을 모두 입력해 등록하면, **Then** 입력한 값 그대로 새 항목이 생성되고 Backlog 칼럼에 나타난다.
2. **Given** 사용자가 설명이나 날짜를 입력하지 않은 상태에서, **When** 제목과 우선순위만 선택해 등록하면, **Then** 입력하지 않은 항목은 빈 값으로 남고 등록은 정상적으로 완료된다.
3. **Given** 사용자가 유효하지 않은 우선순위 값을 지정하려는 상태에서 (예: 시스템이 제공하지 않는 옵션), **When** 등록을 시도하면, **Then** 등록이 거부되고 허용되는 우선순위 값을 안내하는 메시지가 표시된다.
4. **Given** 사용자가 오늘보다 이전 날짜를 종료예정일로 지정한 상태에서, **When** 등록을 시도하면, **Then** 등록이 거부되고 "종료예정일은 오늘 이후 날짜를 선택해주세요"라는 안내가 표시된다.
5. **Given** 사용자가 1000자를 초과하는 설명을 입력한 상태에서, **When** 등록을 시도하면, **Then** 등록이 거부되고 설명 길이 제한을 안내하는 메시지가 표시된다.

---

### Edge Cases

- 제목이 공백 문자로만 이루어진 경우 어떻게 되는가? → 제목 누락과 동일하게 취급되어 거부된다.
- 같은 칼럼(Backlog)에 이미 여러 항목이 있는 상태에서 새로 등록하면 어디에 배치되는가? → 항상 그 칼럼의 맨 위(가장 먼저 보이는 위치)에 배치된다.
- 등록 도중 시스템 내부 오류(예: 저장소 연결 실패)가 발생하면 어떻게 되는가? → 사용자에게 일반적인 오류 발생 안내가 표시되고, 항목은 생성되지 않는다.
- 설명을 명시적으로 비워서 보낸 경우와 아예 보내지 않은 경우는 동일하게 처리되는가? → 두 경우 모두 "설명 없음" 상태로 동일하게 처리된다.
- 우선순위를 지정하지 않으면 어떻게 되는가? → 기본값인 "보통"으로 설정된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 제목만으로 새 할 일을 등록할 수 있게 해야 한다.
- **FR-002**: 시스템은 제목이 비어 있거나 공백 문자로만 이루어진 경우 등록을 거부하고, 사용자에게 제목 입력을 안내해야 한다.
- **FR-003**: 시스템은 제목을 1자 이상 200자 이하로 제한해야 하며, 초과 시 등록을 거부하고 안내해야 한다.
- **FR-004**: 시스템은 사용자가 등록 시 설명(선택), 우선순위(선택), 시작예정일(선택), 종료예정일(선택)을 함께 입력할 수 있게 해야 한다.
- **FR-005**: 시스템은 설명을 1000자 이하로 제한해야 하며, 초과 시 등록을 거부하고 안내해야 한다.
- **FR-006**: 시스템은 우선순위를 "낮음", "보통", "높음" 세 가지 값 중 하나로만 허용해야 하며, 그 외 값이 들어오면 등록을 거부하고 허용값을 안내해야 한다.
- **FR-007**: 시스템은 우선순위가 지정되지 않은 경우 기본값으로 "보통"을 적용해야 한다.
- **FR-008**: 시스템은 종료예정일이 지정된 경우 오늘 이후의 날짜만 허용해야 하며, 과거 날짜가 지정되면 등록을 거부하고 안내해야 한다.
- **FR-009**: 시스템은 새로 등록된 항목을 항상 "할 일 목록(Backlog)" 칼럼에 배치해야 한다.
- **FR-010**: 시스템은 새로 등록된 항목을 해당 칼럼의 다른 모든 항목보다 위(가장 먼저 보이는 위치)에 배치해야 한다.
- **FR-011**: 시스템은 등록이 성공하면 등록된 항목의 전체 정보(사용자가 입력한 값과 시스템이 채운 값 모두 포함)를 사용자에게 확인시켜야 한다.
- **FR-012**: 시스템은 등록 요청이 여러 이유로 유효하지 않을 경우, 어떤 항목이 문제인지 사용자가 식별할 수 있는 방식으로 안내해야 한다.
- **FR-013**: 시스템은 예기치 못한 내부 오류로 등록이 실패한 경우, 사용자에게 일반적인 오류 발생 사실을 안내해야 한다.

### Key Entities

- **할 일 항목(Ticket)**: 사용자가 관리하는 작업 단위. 제목, 설명, 상태(할 일 목록/진행 예정/진행 중/완료 중 하나, 신규 등록 시 항상 "할 일 목록"), 우선순위(낮음/보통/높음), 칼럼 내 표시 순서, 시작예정일, 종료예정일, 실제 시작 시각, 실제 완료 시각, 생성 시각, 마지막 수정 시각을 가진다. 종료예정일이 지났고 아직 완료되지 않은 항목은 "기한 지남" 상태로 함께 표시된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 제목 하나만 입력해 5초 이내에 새 할 일을 등록할 수 있다.
- **SC-002**: 등록된 항목은 별도 새로고침 없이 즉시 목록 맨 위에서 확인할 수 있다.
- **SC-003**: 잘못된 입력(제목 누락, 길이 초과, 잘못된 우선순위, 과거 날짜 등)으로 등록에 실패했을 때, 사용자는 어떤 항목을 어떻게 고쳐야 하는지 메시지만 보고 바로 알 수 있다.
- **SC-004**: 상세 정보(설명, 우선순위, 날짜)를 포함해 등록한 경우, 입력한 값이 하나도 누락되거나 변형되지 않고 그대로 반영된다.

## Assumptions

- MVP 단계에서는 별도의 로그인/인증 없이 단일 사용자가 사용하는 것을 전제로 한다.
- 오류 메시지와 필드 단위 안내는 프로젝트 전반에서 사용하는 공통 오류 응답 규칙을 따른다 (본 문서에서는 사용자 관점의 동작만 기술하고, 구체적인 오류 코드/형식 같은 구현 세부사항은 다루지 않는다).
- 시작 시각/완료 시각은 이번 등록 기능에서는 항상 비어 있는 상태로 시작하며, 이후 다른 기능(상태 이동, 완료 처리)에서 채워진다 — 이번 기능의 책임 범위 밖이다.
- 날짜(시작예정일/종료예정일)는 사용자가 보는 화면 기준 "오늘"과 비교되며, 시간대 처리는 별도 명세하지 않는다.
